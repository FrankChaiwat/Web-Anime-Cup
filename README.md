# Quiz World Cup

เว็บสร้างและเล่นควิซแนว World Cup ด้วย React + TypeScript + Vite, Express + TypeScript และ PostgreSQL

## สิ่งที่มีในเวอร์ชันนี้
- หน้าแรกค้นหาและเลือกควิซ
- หน้าเล่นแบบ World Cup: เลือก 1 จาก 2 ตัวเลือกในแต่ละรอบ
- สมัครสมาชิกและเข้าสู่ระบบ พร้อมเก็บรหัสผ่านแบบ hash
- หน้าแอดมินสำหรับสร้าง แก้ไข และลบควิซ พร้อมอัปโหลดรูปปกควิซ
- หน้าแอดมินสำหรับค้นหาผู้ใช้ด้วยอีเมล แก้ไขบัญชีและลบผู้ใช้
- สมาชิกสร้างควิซของตัวเอง และแก้ไข/ลบควิซเหล่านั้นได้จากหน้าโปรไฟล์
- หน้าโปรไฟล์แสดงควิซของฉัน ประวัติเกมล่าสุด และ 10 ตัวเลือกที่ได้เป็นแชมป์บ่อยที่สุด
- หน้าปัจจุบันและรายการที่เปิดอยู่จะถูกจำไว้เมื่อรีเฟรชเว็บในเบราว์เซอร์เดิม
- อัปโหลดไฟล์ภาพ JPEG, PNG และ WebP (ไม่เกิน 5 MB) แยกตามบัญชีผู้ใช้และชื่อควิซใน `backend/uploads/<user-id>/<ชื่อควิซ>/`
- บันทึกผลผู้ชนะและจำนวนครั้งที่เล่น
- API ตรวจสอบข้อมูลเบื้องต้นและ CORS

## ต้องติดตั้งก่อน
- Node.js รุ่น LTS
- PostgreSQL (หรือ PostgreSQL ผ่าน Docker)
- VS Code (แนะนำ)

## 1. สร้างฐานข้อมูล
เปิด pgAdmin หรือ psql แล้วรัน:
```sql
CREATE DATABASE quiz_worldcup;
```

## 2. ตั้งค่า Backend
เปิด PowerShell ในโฟลเดอร์ `backend`:
```powershell
Copy-Item .env.example .env
npm install
```
แก้ `backend/.env` ให้ตรงกับเครื่อง เช่น:
```env
PORT=5000
DATABASE_URL=postgresql://postgres:รหัสผ่านของคุณ@localhost:5432/quiz_worldcup
CLIENT_URL=http://localhost:5173
SESSION_SECRET=
ADMIN_EMAIL=
ADMIN_PASSWORD=
```
ถ้ารหัสผ่านมีอักขระพิเศษ เช่น `@`, `#`, `/` ให้ URL-encode รหัสผ่านก่อนใส่ใน DATABASE_URL

สร้างค่า secret ด้วยคำสั่ง `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` แล้วนำผลลัพธ์ใส่ `SESSION_SECRET` (อย่างน้อย 32 bytes) กำหนด `ADMIN_EMAIL` และ `ADMIN_PASSWORD` พร้อมกันเพื่อสร้างบัญชีแอดมินเริ่มต้น (รหัสผ่านอย่างน้อย 12 ตัวอักษร) หากแก้รหัสผ่านใน `.env` ระบบจะอัปเดตบัญชีนี้เมื่อเริ่ม backend ครั้งถัดไป บัญชีที่สมัครจากหน้าเว็บจะเป็นสมาชิกทั่วไปและไม่ได้รับสิทธิ์แอดมิน

เริ่มเซิร์ฟเวอร์:
```powershell
npm run dev
```
เมื่อเชื่อมต่อสำเร็จ API จะสร้างตารางที่จำเป็นให้อัตโนมัติ ส่วนโฟลเดอร์สำหรับภาพจะถูกสร้างแยกตามชื่อควิซเมื่อมีการอัปโหลดครั้งแรก ดูรายละเอียดในหัวข้อ [การจัดเก็บและอัปโหลดรูปภาพ](#การจัดเก็บและอัปโหลดรูปภาพ)

## 3. ตั้งค่า Frontend
เปิด PowerShell อีกหน้าต่าง ในโฟลเดอร์ `frontend`:
```powershell
Copy-Item .env.example .env
npm install
npm run dev
```
เข้าเว็บที่ http://localhost:5173

## การจัดเก็บและอัปโหลดรูปภาพ

ภาพปกควิซและภาพของตัวเลือกใช้ API อัปโหลดเดียวกัน โดยไฟล์จริงจะอยู่บนดิสก์ของเครื่องที่รัน backend ภายใน `backend/uploads` และแยกโฟลเดอร์ตามชื่อควิซ ตัวอย่างเช่น ถ้าชื่อควิซคือ `Anime World Cup` โครงสร้างจะมีลักษณะดังนี้:

```text
backend/
└── uploads/
    ├── user-12/
    │   └── quiz-anime-world-cup/
    │       ├── 27eab74b-....jpg
    │       └── c3b614f1-....png
    └── user-37/
        └── quiz-anime-world-cup/
            └── 2d4b8a91-....webp
```

โฟลเดอร์ `user-<id>` แยกตามบัญชีที่เข้าสู่ระบบ โดยใช้รหัสบัญชีภายในที่ไม่ซ้ำกันแทนชื่อที่แสดง เพื่อป้องกันชื่อซ้ำกันชนกันและไม่ต้องย้ายรูปเมื่อผู้ใช้เปลี่ยนชื่อ ส่วนโฟลเดอร์ควิซไม่ได้ใช้ชื่อควิซดิบโดยตรง แต่ระบบปรับชื่อให้ปลอดภัย: เปลี่ยนเป็นตัวพิมพ์เล็ก, แทนอักขระที่ไม่ใช่ตัวอักษรหรือตัวเลขด้วย `-`, ตัด `-` ที่หัวและท้าย และเติมคำนำหน้า `quiz-` ตัวอักษรไทยและภาษาอื่นที่เป็นตัวอักษร/ตัวเลขยังใช้ได้ หากชื่อไม่มีอักขระที่ใช้ได้ จะใช้ `quiz-untitled` ชื่อไฟล์แต่ละภาพเป็น UUID แบบสุ่ม

### ขั้นตอนจากหน้าสร้างหรือแก้ไขควิซ

1. ผู้ใช้ต้องเข้าสู่ระบบก่อนสร้างควิซ; ชื่อควิซต้องมีความยาว 3–120 ตัวอักษร
2. เลือกไฟล์สำหรับภาพปกหรือภาพของตัวเลือก ระบบส่งชื่อควิซและไฟล์ไป backend
3. backend ตรวจสิทธิ์บัญชีที่เข้าสู่ระบบ ตรวจชนิดและเนื้อหาไฟล์ แล้วบันทึกไฟล์ลงในโฟลเดอร์ของควิซ
4. เมื่อบันทึกสำเร็จ API ส่ง URL ของภาพกลับมา และหน้าสร้าง/แก้ไขควิซนำ URL นั้นไปใส่ในช่องรูปภาพของควิซหรือตัวเลือก

รองรับ JPEG, PNG และ WebP ขนาดไม่เกิน 5 MB ต่อไฟล์ และรับภาพได้ครั้งละหนึ่งไฟล์ต่อคำขอ ชื่อควิซต้องถูกส่งมากับ multipart field ชื่อ `quizTitle` ก่อน field ไฟล์ `image` ส่วนการอัปโหลดจากหน้าเว็บจัดลำดับให้อัตโนมัติ หากเรียก API เอง ต้องส่งทั้งสอง field โดยใช้ `multipart/form-data` และแนบ token ของบัญชีที่เข้าสู่ระบบ:

```text
POST /api/uploads
Authorization: Bearer <admin-token>
Content-Type: multipart/form-data

quizTitle = Anime World Cup
image     = <ไฟล์ภาพ>
```

เมื่อสำเร็จ API ตอบสถานะ `201` พร้อม URL เช่น `/uploads/user-12/quiz-anime-world-cup/27eab74b-....jpg` URL นี้ใช้แสดงภาพผ่าน backend ได้ รูปของแต่ละบัญชีจะอยู่ในโฟลเดอร์ `user-<id>` ของตน ระบบตรวจทั้งชนิด MIME และลายเซ็นข้อมูลจริงของไฟล์ ไม่รับไฟล์ที่แค่เปลี่ยนนามสกุลให้ดูเหมือนภาพ

ภาพที่อัปโหลดจะไม่ย้ายตามเมื่อแก้ชื่อควิซภายหลัง ไฟล์จะอยู่ในโฟลเดอร์ของบัญชีและชื่อควิซ ณ เวลาที่อัปโหลด แต่ URL ที่บันทึกไว้ยังอ้างถึงภาพเดิมได้ หากต้องการจัดโฟลเดอร์ให้ตรงกับชื่อใหม่ ให้อัปโหลดภาพอีกครั้ง รูปแบบ URL เก่าที่เก็บตรง `backend/uploads` หรือมีเฉพาะโฟลเดอร์ควิซยังแสดงและบันทึกต่อได้

### เปลี่ยนภาพประกอบหน้าแรก

แอดมินเปลี่ยนภาพตัวละครบนการ์ดด้านขวาและภาพพื้นหลังเต็มแถบต้อนรับของหน้าแรกได้จากหน้า **จัดการควิซ** เลือกไฟล์ JPEG, PNG หรือ WebP แล้วระบบจะอัปโหลดและบันทึกการตั้งค่าให้โดยอัตโนมัติ พื้นหลังจะมีชั้นสีโปร่งทับภาพเพื่อช่วยให้ข้อความอ่านชัด ภาพทั้งสองส่วนจะถูกจัดเก็บในโฟลเดอร์ของบัญชีแอดมิน เช่น `backend/uploads/user-1/quiz-ภาพการ์ดหน้าแรก/` และแสดงแก่ผู้เข้าชมทุกคน สามารถคืนค่าภาพการ์ดเริ่มต้นหรือพื้นหลังไล่สีเดิมแยกจากกันได้ ไฟล์ที่เคยอัปโหลดจะไม่ถูกลบออกจากดิสก์โดยอัตโนมัติ

การตั้งค่านี้เก็บไว้ในตาราง `site_settings` ของ PostgreSQL:

- `GET /api/site-settings/homepage` อ่าน URL ภาพการ์ดและภาพพื้นหลัง (เปิดให้หน้าเว็บเรียกได้โดยไม่ต้องเข้าสู่ระบบ)
- `PUT /api/site-settings/homepage` บันทึก `heroImageUrl` หรือ `heroBackgroundUrl`; ส่งค่าว่างในฟิลด์ที่ต้องการเพื่อคืนค่าเริ่มต้น (แอดมินเท่านั้น)

ควิซที่สร้างหลังเพิ่มระบบเจ้าของจะบันทึก `owner_user_id` ใน PostgreSQL และแสดงในส่วน **ควิซของฉัน** บนหน้าโปรไฟล์ สมาชิกแก้ไขหรือลบได้เฉพาะควิซที่ตนเป็นเจ้าของ ส่วนแอดมินยังคงจัดการควิซทั้งหมดได้ ควิซเดิมที่ไม่มีเจ้าของยังเล่นได้และจัดการได้โดยแอดมิน

## API หลัก
- `GET /api/health` ตรวจสอบ API
- `POST /api/auth/register` สมัครสมาชิก
- `POST /api/auth/login` เข้าสู่ระบบ
- `GET /api/auth/me` ตรวจสอบบัญชีปัจจุบัน (ต้องมี Bearer token)
- `GET /api/profile` ดูประวัติการเล่นและ 10 ตัวเลือกที่ได้เป็นแชมป์บ่อยที่สุด (ต้องมี Bearer token)
- `GET /api/admin/users?search=email` ค้นหารายชื่อผู้ใช้ด้วยอีเมล (แอดมินเท่านั้น)
- `PUT /api/admin/users/:id` แก้ไขชื่อ อีเมล สิทธิ์ หรือกำหนดรหัสผ่านใหม่ (แอดมินเท่านั้น)
- `DELETE /api/admin/users/:id` ลบผู้ใช้ (แอดมินเท่านั้น; ป้องกันการลบตัวเองหรือแอดมินคนสุดท้าย)
- `GET /api/quizzes?search=anime` ดูควิซ / ค้นหา
- `GET /api/quizzes/:id` ดูควิซพร้อมตัวเลือก
- `POST /api/uploads` อัปโหลดภาพ (บัญชีที่เข้าสู่ระบบ, multipart fields `quizTitle` และ `image`)
- `POST /api/quizzes` สร้างควิซและกำหนดเจ้าของเป็นบัญชีที่เข้าสู่ระบบ
- `PUT /api/quizzes/:id` แก้ไขควิซของตัวเอง; แอดมินแก้ไขได้ทุกควิซ
- `DELETE /api/quizzes/:id` ลบควิซของตัวเอง; แอดมินลบได้ทุกควิซ
- `POST /api/quizzes/:id/plays` บันทึกผลการเล่น

ผลการเล่นหลังเข้าสู่ระบบจะถูกเก็บในโปรไฟล์พร้อมแชมป์ที่เลือกและชื่อควิซ ณ เวลานั้น อันดับ 10 คำนวณจากจำนวนครั้งที่เลือกตัวเลือกนั้นเป็นแชมป์ ส่วนการเล่นแบบไม่เข้าสู่ระบบจะไม่ถูกรวมในโปรไฟล์

## หมายเหตุ
- อัปโหลดภาพจะบันทึกไฟล์ไว้ในเครื่องเซิร์ฟเวอร์และไม่รวมใน Git ดังนั้นควรตั้งค่า persistent storage และสำรองข้อมูล `backend/uploads` เมื่อ deploy
- กำหนด HTTPS, CORS ให้ตรงกับโดเมนจริง และใช้ `SESSION_SECRET`/รหัสผ่านแอดมินที่ปลอดภัยใน production

├── frontend/                   # เว็บ React

`dist`, `node_modules`, `.env` และ `backend/uploads` เป็นโฟลเดอร์/ไฟล์ที่สร้างหรือเติมข้อมูลระหว่างติดตั้งและใช้งาน ไม่จำเป็นต้องสร้างเองล่วงหน้า และถูกตั้งค่าไม่ให้ส่งเข้า Git (ยกเว้น `.env.example` ที่เป็นไฟล์ตัวอย่าง) ตารางและข้อมูลควิซ/ผู้ใช้จะอยู่ใน PostgreSQL ไม่ได้เก็บเป็นไฟล์ในโฟลเดอร์โปรเจกต์
